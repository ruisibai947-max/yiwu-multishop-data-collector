# 比特浏览器配置与账号分配操作指南

## 1. 适用范围

本指南用于客户专用 Windows 电脑上的 Temu、Shein、TikTok Shop、京东、聚水潭等后台账号。目标是保持长期稳定的登录环境，供人工操作和每日自动采集使用。

本项目不使用比特浏览器绕过验证码、规避平台限制或伪造异常登录环境。账号首次登录、短信、扫码、动态验证码和设备验证均由客户人员完成。

## 2. 核心分配规则

隔离单位是“独立登录账号”，不是平台、店铺或浏览器标签页：

```text
一个独立登录账号
-> 一个固定比特浏览器窗口
-> 该账号能够切换的一个或多个店铺
```

例如：

```text
比特窗口 TEMU-A001
└── Temu 登录账号 A001
    ├── 店铺 001
    ├── 店铺 002
    └── 店铺 003
```

- 一个账号管理三个店铺：创建一个窗口。
- 三个独立账号分别管理一个店铺：创建三个窗口。
- 不同平台即使使用相同邮箱，也分别创建窗口。
- 同一窗口中的标签页共享 Cookie，不能用标签页隔离两个账号。
- 自动采集期间，不允许员工同时操作同一窗口。

建议分组：

```text
01-TEMU
02-SHEIN
03-TIKTOK-SHOP
04-JD
05-JUSHUITAN
90-等待验证
99-暂停或停用
```

建议窗口名称：

```text
平台-账号编号-负责人
```

例如 `TEMU-A001-张三`、`TIKTOK-US-A003-李四`。

## 3. Windows 和 VPN 前置设置

1. 使用固定的 Windows 业务账号。
2. 使用稳定的公司网络，优先有线连接。
3. Windows 时区保持实际所在地。
4. 关闭自动睡眠和非必要自动重启。
5. VPN 使用“规则模式”或“应用分流”，不要使用不断切换节点的全局模式。
6. Codex 走 VPN；比特浏览器、`127.0.0.1` 和局域网地址走直连。

理想网络路径：

```text
Codex -> VPN 出口
比特浏览器店铺窗口 -> 公司公网出口
比特浏览器 Local API -> 127.0.0.1 本机直连
```

如果 VPN 使用 TUN 或虚拟网卡模式，仅在比特浏览器中选择“直连”不一定能绕过 VPN。必须在 VPN 客户端中把比特浏览器主程序及其浏览器内核进程加入“直连/绕过代理”。

配置后分别访问 `https://ipinfo.io`；若直连网络无法访问，可使用 `https://www.ip138.com/`：

1. 普通外网浏览器应显示 VPN 出口。
2. 比特浏览器窗口应显示公司网络出口。
3. 多次关闭、打开窗口后，比特浏览器出口国家或地区不应变化。

## 4. 创建窗口：基础信息

先为每个平台创建一个测试窗口。完成连续验证后，再批量建立其余窗口。

| 字段 | 建议填写 |
| --- | --- |
| 窗口名称 | `平台-账号编号-负责人` |
| 分组 | 对应平台分组 |
| 平台 URL | 员工日常使用的官方商家后台登录地址 |
| 用户名 | 留空 |
| 密码 | 留空 |
| 校验重复项 | 不勾选 |
| 多开设置 | 不允许 |
| 2FA 密钥 | 留空 |
| 备注 | 账号编号、主体、负责人、店铺数量、验证方式、用途 |
| Cookie | 留空 |
| 打开指定网址 | 试点阶段留空 |

备注示例：

```text
账号编号：TEMU-A001
主体：义乌XX公司
负责人：张三
管理店铺：5家
验证方式：张三手机短信
用途：每日财务报表采集
```

备注中禁止记录密码、Cookie、2FA 密钥、短信验证码和身份证信息。

“平台 URL”应使用员工平时登录的官方后台入口，不使用搜索结果、宣传首页、第三方跳转链接或包含临时令牌的长链接。

## 5. 代理设置

在 VPN 已正确分流的前提下：

```text
代理方式：自定义代理
IP 查询渠道：IP2Location 或软件默认值
代理类型：直连模式（不设置代理）
```

此设置表示窗口使用 Windows 的实际网络路径。若 VPN 是全局或 TUN 接管，比特浏览器仍可能经过 VPN，因此必须使用 `ipinfo.io` 实测，不能只看界面配置。

只有账号历史上长期使用固定海外办公室网络、固定业务代理，或平台明确要求指定地区时，才配置 HTTP、HTTPS 或 SOCKS5 代理。代理必须由客户提供并确认，不使用免费代理、动态住宅 IP、随机国家代理或每次启动更换 IP。

## 6. 常用设置

蓝色表示开启，灰色表示关闭。

### 6.1 页面和安全

| 设置项 | 建议 |
| --- | --- |
| 浏览器窗口工作台页面 | 不显示 |
| 禁止加载图片 | 关闭 |
| 禁止视频自动播放/预加载 | 开启 |
| 禁止网站播放声音 | 开启 |
| 禁止浏览器弹出谷歌翻译 | 开启 |
| 禁止保存密码弹窗 | 开启 |
| 禁止网页弹出消息通知 | 开启 |
| 禁止网站读取剪贴板内容 | 关闭 |
| 网络不通停止打开 | 开启 |
| IP 发生变化停止打开 | 关闭 |
| IP 对应国家/地区变化停止打开 | 开启 |

首次启用“IP 对应国家/地区变化停止打开”前，必须先确认比特窗口显示的是正常业务出口地区，而不是 VPN 节点地区。

### 6.2 云同步

本项目要求登录状态和客户数据保留在客户专用 Windows 电脑，因此以下同步项全部关闭：

```text
同步标签页：关闭
同步 Cookie：关闭
同步 IndexedDB：关闭
同步 Local Storage：关闭
同步书签：关闭
同步已保存的用户名密码：关闭
同步历史记录：关闭
同步扩展应用数据：关闭
```

关闭“同步 Cookie”只是不将 Cookie 同步到比特浏览器云端，不会删除当前 Windows 电脑上该窗口的本地 Cookie。

### 6.3 启动前清理

以下全部关闭：

```text
启动浏览器前删除缓存文件
启动前删除缓存（保留扩展数据）
启动浏览器前删除 Cookie
启动浏览器前删除历史记录
```

“启动浏览器前删除 Cookie”必须关闭，否则可能每次启动都需要重新登录。

### 6.4 性能

| 设置项 | 建议 |
| --- | --- |
| 启动浏览器时随机指纹 | 关闭 |
| 允许登录 Chrome | 关闭 |
| 使用硬件加速模式 | 开启 |
| 省内存模式 | 关闭 |

## 7. 指纹设置

原则是创建窗口时生成一次完整、相互匹配的参数，保存后长期固定使用。不要每天更换操作系统、User Agent、Canvas、WebGL 或设备信息。

### 7.1 基础参数

| 项目 | 推荐设置 |
| --- | --- |
| 浏览器 | BitBrowser |
| 浏览器内核版本 | 软件默认的当前稳定版本 |
| 设备 | 电脑 |
| 操作系统 | Windows |
| 操作系统版本 | 与专用电脑实际 Windows 版本一致 |
| 浏览器版本 | 与所选内核匹配 |
| User Agent | 让比特浏览器自动生成 |
| 语言 | 基于 IP 生成，开启 |
| 界面语言 | 跟随 Windows 系统 |
| 时区 | 基于 IP 生成，开启 |

按 `Win + R`，输入 `winver` 可确认 Windows 版本。Windows 11 的 User Agent 中显示 `Windows NT 10.0` 属于兼容行为，不手工修改。

### 7.2 网络与显示

| 项目 | 推荐设置 |
| --- | --- |
| WebRTC | 隐私 |
| 忽略 HTTPS 证书错误 | 关闭 |
| 地理位置权限 | 询问 |
| 基于 IP 生成地理位置 | 开启 |
| 窗口尺寸 | 1600 x 900；小屏电脑可用 1280 x 720 |
| 分辨率 | 跟随电脑 |
| 字体 | 系统默认 |

### 7.3 浏览器特征

以下“随机”表示创建窗口时为该窗口生成一套固定参数。只要“启动浏览器时随机指纹”关闭，后续启动不会重新随机。

| 项目 | 推荐设置 |
| --- | --- |
| Canvas | 随机 |
| WebGL 图像 | 随机 |
| WebGL 元数据 | 自定义，由软件自动生成 |
| WebGL 厂商和渲染 | 点击“换一换”自动生成，不手工编造 |
| AudioContext | 随机 |
| 媒体设备 | 关闭 |
| Speech Voices | 随机 |
| Do Not Track | 关闭 |
| ClientRects | 随机 |
| 设备信息 | 自定义，由软件自动生成 |

### 7.4 设备与安全

| 项目 | 推荐设置 |
| --- | --- |
| 设备名称 | 点击一次“换一换”自动生成 |
| Host IP | 自动生成，不修改 |
| MAC 地址 | 自动生成，不修改 |
| 端口扫描保护 | 开启 |
| 扫描白名单 | 留空 |
| SSL 指纹设置 | 关闭 |
| 自定义插件指纹 | 关闭 |
| 硬件并发数 | 跟随电脑 |
| 设备内存 | 4GB 或 8GB；电脑内存不少于 8GB 时选 8GB |
| 启动参数 | 留空 |

不要将硬件并发数手工设置成 `32` 等与普通业务电脑明显不匹配的值。不要填写大于 8GB 的浏览器设备内存指纹值。

## 8. 首次登录与验证

1. 保存并打开测试窗口。
2. 访问 `https://ipinfo.io` 或 `https://www.ip138.com/`，确认出口国家或地区正确。
3. 人工输入平台账号密码。
4. 人工完成短信、邮箱、扫码、动态验证码或设备验证。
5. 检查账号身份及其可切换的全部店铺。
6. 手工进入目标报表页面并下载一次测试报表。
7. 关闭窗口后重新打开，确认仍保持登录。
8. 重启 Windows 后再次打开，确认登录和网络出口稳定。
9. 连续试运行两到三天，再扩大账号数量。

登录失效时，必须打开原窗口重新登录。不要新建窗口替代，否则原窗口 Cookie 和设备环境不会被复用。

## 9. 账号、窗口和店铺登记

登记的目的，是让自动化系统知道采集某家店铺时应打开哪个比特浏览器窗口。

关系如下：

```text
browser_profile -> account -> one or more shops
```

先填写：

[`account-shop-environment-inventory.csv`](./templates/account-shop-environment-inventory.csv)

一个账号管理三家店铺时填写三行，三行使用相同的 `browser_profile_id`。

关键字段：

| 字段 | 内容 |
| --- | --- |
| platform | 平台代码 |
| login_account | 内部账号编号或非敏感名称 |
| account_owner | 负责人 |
| login_method | 密码、短信、扫码、2FA 等 |
| browser_provider | `bitbrowser` |
| browser_profile_id | 比特浏览器窗口 ID |
| shop_id | 平台店铺 ID |
| shop_name | 店铺名称 |
| employee_concurrent_use | 是否需要员工同时使用 |
| notes | 非敏感补充说明 |

登记表禁止填写密码、Cookie、2FA 密钥和验证码。

## 10. 获取比特浏览器窗口 ID

保持比特浏览器客户端运行，在 PowerShell 执行：

```powershell
Invoke-RestMethod `
  -Method Post `
  -Uri "http://127.0.0.1:54345/health" `
  -ContentType "application/json" `
  -Body "{}"
```

查询窗口列表：

```powershell
Invoke-RestMethod `
  -Method Post `
  -Uri "http://127.0.0.1:54345/browser/list" `
  -ContentType "application/json" `
  -Body '{"page":0,"pageSize":100}'
```

返回结果中的窗口 `id` 填入 `browser_profile_id`。本地 API 地址若在比特浏览器设置中被修改，应以客户端显示的实际地址为准。

## 11. 批量上线顺序

```text
每个平台一个代表账号
-> 连续验证两到三天
-> 每个平台扩大到三个账号
-> 确认登录、报表、IP 和自动采集稳定
-> 再批量建立剩余窗口
```

不要复制某个已登录窗口作为其他账号的登录环境，也不要把一个账号的 Cookie 导入其他账号。

## 12. 现场确认清单

- [ ] Windows 固定业务账号、时区、网络和休眠策略已确认。
- [ ] VPN 已分流，Codex 走 VPN，比特浏览器走业务出口。
- [ ] `127.0.0.1` 和局域网地址不经过 VPN。
- [ ] 每个独立登录账号只绑定一个固定比特窗口。
- [ ] 云同步、启动前清理和每次启动随机指纹均关闭。
- [ ] 比特窗口出口地区与账号正常使用环境一致。
- [ ] 操作系统、浏览器版本、User Agent 和设备参数相互匹配。
- [ ] 首次登录、店铺切换、报表下载和登录持久化验证通过。
- [ ] 窗口 ID、账号、店铺和负责人已登记。
- [ ] 密码、Cookie、2FA 密钥和验证码未写入登记表或备注。
