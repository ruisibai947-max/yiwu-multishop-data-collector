# 驻场前检查清单

## 1. 人员与时间

- [ ] 老板或最终决策人明确第一阶段目标和延长驻场机制。
- [ ] 9 位财务人员中至少指定 1 位口径负责人、1 位日常操作负责人。
- [ ] Temu 商品运营指定 1 位商品链接数据负责人。
- [ ] 每个平台至少有 1 位熟悉后台导出流程的员工可现场配合。
- [ ] 预留连续两天定时采集验证窗口和一次手动采集验证窗口。
- [ ] 约定每天的需求确认、问题复盘和签字时间。

## 2. 专用 Windows 电脑

- [ ] 确认 Windows 版本、CPU、内存、磁盘剩余空间。
- [ ] 确认电脑可长期通电，关闭自动睡眠和非必要自动重启。
- [ ] 确认安装 Node.js 24 LTS、Codex、比特浏览器的权限。
- [ ] 确认安全软件不会阻止本地端口、Playwright、Node.js 或比特浏览器 Local API。
- [ ] 确认项目、运行数据和备份目录均位于客户电脑。
- [ ] 确认远程维护方式以及需要客户确认的操作边界。

## 3. 比特浏览器与账号

- [ ] 携带并按[《比特浏览器配置与账号分配操作指南》](./bitbrowser-configuration-guide.md)逐项配置。
- [ ] 导出全部平台登录账号、店铺、站点和负责人清单。
- [ ] 确认一个登录账号对应一个固定比特浏览器环境。
- [ ] 标记同一账号下管理的全部店铺，不假设一店一号。
- [ ] 确认 VPN 已分流：Codex 走 VPN，比特浏览器和 Local API 直连。
- [ ] 关闭比特浏览器云端 Cookie、密码、Local Storage 等同步项。
- [ ] 确认哪些现有环境可迁移到专用电脑，哪些必须原地使用。
- [ ] 每个平台预选至少两个有代表性的测试店铺。
- [ ] 确认验证码、短信、邮箱、扫码和二次验证的人工处理人。

## 4. 数据与口径

- [ ] 收集财务当前每日手工导出的报表样例。
- [ ] 收集每个平台后台的菜单路径、筛选条件和总计位置。
- [ ] 明确 GMV、退款、投流费用等指标当前内部口径。
- [ ] 明确业务日期、时区、币种、退款归属日和数据延迟。
- [ ] 明确 Temu 商品链接 ID 的来源、批量查询入口和过去 30 天窗口。
- [ ] 明确第一阶段允许使用的测试日期和脱敏要求。

## 5. API、费用与外部系统

- [ ] 现场优先核验官方 API 能力、申请条件、费用和限流。
- [ ] 未经老板确认，不开通产生费用的 API 或云服务。
- [ ] 准备飞书测试多维表格，但不提前固定最终展示结构。
- [ ] 确认是否允许在客户电脑访问 npm、Git、飞书和平台后台。

## 6. 数据安全

- [ ] 真实密码、Cookie、验证码和原始数据不得复制到开发者个人电脑。
- [ ] 凭证仅通过 Windows DPAPI 保存在客户电脑当前业务账号下。
- [ ] 截图、录屏、报表和网络证据保存到客户本地 evidence 目录。
- [ ] 飞书通知不包含密码、Cookie、验证码、响应头或报表明细。
- [ ] 约定源码、部署包、操作文档和客户数据的正式交付边界。

## 7. 携带与验证

- [ ] 当前代码仓库和中文实施计划。
- [ ] Windows 安装、启动、停止、备份和计划任务脚本。
- [ ] 本驻场模板工作包。
- [ ] 模拟适配器端到端测试结果。
- [ ] 准备离线 Node.js 安装包和必要依赖缓存方案。
