# 驻场开发执行清单

> **驻场启动入口：到达客户现场后，必须先执行本节，再继续后面的“一、到场后先确认边界”。**
>
> 本清单是现场工作的主执行入口。每完成一项就在复选框中标记；现场情况与清单不一致时，先记录实际证据，再调整实施方案，不要凭猜测编写平台采集代码。

## 驻场启动入口（必须先执行）

### 1. 准备客户电脑

- [ ] 使用客户指定的 Windows 业务账号登录。
- [ ] 确认该账号有安装软件、运行 PowerShell 和创建计划任务的权限。
- [ ] 安装 Git、Node.js 24 LTS、Codex 和比特浏览器。
- [ ] 确认客户电脑能够访问 GitHub、npm 和各平台后台。

### 2. 从私有 GitHub 仓库获取代码

- [ ] 在客户电脑打开 PowerShell。
- [ ] 克隆私有仓库：

```powershell
cd C:\
git clone https://github.com/resbaict/yiwu-multishop-data-collector.git YiwuCollector
cd C:\YiwuCollector
git status
```

- [ ] 确认当前分支为 `main`，并且工作区没有未提交修改。
- [ ] 如果克隆时使用了开发者个人 GitHub 账号，代码下载完成后退出账号并清理不再需要的个人访问凭证。
- [ ] 不要把 GitHub 密码、访问令牌或 SSH 私钥写入项目配置文件。

### 3. 让现场 Codex 读取项目

- [ ] 在 Codex 中打开 `C:\YiwuCollector` 项目目录。
- [ ] 将下面这段内容作为现场 Codex 的第一条任务指令：

```text
请先阅读以下文件，理解本项目的架构、边界和第一阶段验收标准，暂时不要修改代码：

1. docs/fieldwork/驻场开发执行清单.md
2. docs/fieldwork/onsite-runbook.md
3. docs/fieldwork/pre-onsite-checklist.md
4. docs/fieldwork/windows-deployment.md
5. docs/superpowers/specs/2026-06-14-multiplatform-data-automation-design.md
6. docs/superpowers/plans/2026-06-14-第一阶段-公共底座与驻场验证-中文.md

阅读后请：
1. 复述第一阶段目标、数据安全边界和验收标准；
2. 检查当前电脑环境和代码仓库状态；
3. 根据“驻场开发执行清单”告诉我现在应该执行的第一项工作；
4. 在获得真实人工流程、页面证据和样例报表之前，不编造平台选择器、接口或数据口径。
```

- [ ] 检查 Codex 的复述是否包含以下关键点：
  - 五个平台各至少验证 2 家店铺。
  - Temu 商品链接验证 2 家店铺、每店至少 2 个链接。
  - 连续 2 天自动采集成功，并完成 1 次手动采集。
  - 客户密码、Cookie、验证码和原始数据不得离开客户电脑。
  - 多个平台可以并行开发，不必等待一个平台完成观察期。

### 4. 开始按清单执行

- [ ] 从下一节“一、到场后先确认边界”开始逐项执行。
- [ ] 每完成一个重要步骤，记录结果、证据文件位置和未解决问题。
- [ ] 真实平台开发使用独立功能分支，不直接在 `main` 上试错。
- [ ] 每次提交前检查不得包含客户报表、数据库、截图、日志、Cookie 或凭证。
- [ ] 验证通过后再合并回 `main` 并推送私有仓库。

**本节完成标志：** 代码已克隆、个人 GitHub 凭证已妥善处理、Codex 已读取项目文档，并开始执行第一项现场检查。

## 一、到场后先确认边界

- [ ] 指定 1 位项目决策人，负责范围、费用和延期决策。
- [ ] 指定 1 位财务口径负责人，负责确认 GMV、退款、投流费用等口径。
- [ ] 指定 1 位日常操作负责人，负责后续手动采集、登录恢复和异常处理。
- [ ] 指定 1 位 Temu 商品运营负责人，负责商品链接数据确认。
- [ ] 每个平台指定至少 1 位熟悉后台操作的员工。
- [ ] 确认第一阶段验收范围：
  - Temu、Shein、TikTok Shop、京东、聚水潭各至少 2 家店铺。
  - Temu 商品链接至少 2 家店铺，每店至少 2 个商品链接。
  - 连续 2 天自动采集成功，并验证 1 次手动采集。
- [ ] 再次确认：3 至 5 天不足时允许延长驻场，不以牺牲准确性强行结束。
- [ ] 真实密码、Cookie、验证码、原始数据不得复制到个人电脑。
- [ ] 未经老板确认，不开通收费 API、云数据库或其他收费服务。

**本步骤产出：** 项目负责人名单、验收范围、费用审批人、数据安全边界。

## 二、检查专用 Windows 电脑

- [ ] 记录 Windows 版本、CPU、内存和磁盘剩余空间。
- [ ] 确认电脑可长期通电，关闭自动睡眠。
- [ ] 确认当前 Windows 业务账号可安装软件和创建计划任务。
- [ ] 确认 Node.js 24 LTS、Git、Codex 和比特浏览器可用。
- [ ] 确认安全软件不会拦截 Node.js、本地端口和比特浏览器 Local API。
- [ ] 确认 GitHub、npm、飞书和各平台后台可以访问。
- [ ] 确认项目固定目录为 `C:\YiwuCollector`。
- [ ] 确认运行数据固定保存在 `C:\YiwuCollector\runtime`。
- [ ] 确认该目录不会同步到个人网盘。

**本步骤产出：** 电脑环境记录、缺失软件和权限问题清单。

## 三、部署公共底座

- [ ] 将私有仓库克隆到客户电脑，不长期保留个人 GitHub 凭证。
- [ ] 在项目根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\windows\install.ps1
```

- [ ] 启动系统：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\windows\start.ps1
```

- [ ] 检查服务：

```powershell
Invoke-RestMethod http://127.0.0.1:4310/health
```

- [ ] 打开 `http://127.0.0.1:4310/`，确认管理端正常显示。
- [ ] 使用模拟适配器完成 1 次手动采集。
- [ ] 确认任务记录、原始文件、标准数据和本地预览均已生成。
- [ ] 执行一次备份并确认备份文件存在：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\windows\backup.ps1
```

**本步骤产出：** 可运行的公共底座、健康检查结果、模拟采集记录、首份备份。

## 四、盘点账号、店铺和比特浏览器环境

- [ ] 填写 `templates/account-shop-environment-inventory.csv`。
- [ ] 记录每个平台的登录账号、账号负责人和二次验证方式。
- [ ] 记录每个账号管理的全部店铺，不假设一个账号只对应一家店。
- [ ] 每个登录账号绑定一个固定的比特浏览器环境。
- [ ] 不让不同账号共用 Cookie、缓存或浏览器环境。
- [ ] 确认比特浏览器 Local API 已开启。
- [ ] 测试程序能通过 Local API 打开指定环境并连接 CDP。
- [ ] 测试关闭程序后，浏览器环境中的登录状态仍可保留。
- [ ] 明确登录失效、短信、扫码和验证码由谁处理。
- [ ] 为每个平台选定至少 2 家有代表性的测试店铺。

**本步骤产出：** 完整账号店铺清单、环境 ID、验证责任人、测试店铺名单。

## 五、完整观察人工流程

每个平台和每类数据都必须先完整观察一次人工操作，再开始写适配器。

- [ ] 让财务人员从登录开始，完整演示 Temu 财务数据导出。
- [ ] 完整演示 Shein 财务数据导出。
- [ ] 完整演示 TikTok Shop 财务数据导出。
- [ ] 完整演示京东财务数据导出。
- [ ] 完整演示聚水潭财务数据导出。
- [ ] 让 Temu 运营完整演示商品链接 ID 的获取与批量查询。
- [ ] Temu 重点确认是否从“商品分析/过去 30 天上新产品”获取。
- [ ] 每种流程填写 `templates/manual-workflow-record.md`。
- [ ] 记录后台菜单路径、筛选条件、日期范围、站点、币种和店铺切换方法。
- [ ] 记录报表生成等待时间、分页、单次最大导出量和批量链接上限。
- [ ] 记录总计显示位置，以及页面总计与导出文件是否一致。
- [ ] 将截图、录屏、样例报表和网络观察证据保存在客户电脑 `evidence` 目录。

**本步骤产出：** 每个平台的人工流程记录、样例报表、操作证据和限制条件。

## 六、冻结数据口径

- [ ] 填写 `templates/report-field-metric-catalog.csv`。
- [ ] 明确每个指标在平台中的原始字段名。
- [ ] 明确 GMV 是下单、支付、结算还是其他口径。
- [ ] 明确退款金额、退款日期和退款归属方式。
- [ ] 明确投流费用包含哪些广告产品和账户。
- [ ] 明确业务日期、平台时区和系统展示时区。
- [ ] 明确币种、原币金额和汇率换算规则。
- [ ] 明确空值、零值、缺失行和延迟更新的处理方式。
- [ ] 明确店铺、站点、账号和主体的映射关系。
- [ ] 明确 Temu 商品链接的曝光、点击率、加购率、转化率和 GMV 口径。
- [ ] 让财务或运营口径负责人确认第一阶段字段。
- [ ] 未确认的字段不进入正式经营汇总。

**本步骤产出：** 已确认的数据字典、指标口径、筛选条件和对账基准。

## 七、为每个数据集选择采集方式

按以下顺序选择，优先使用风险更低、更稳定的方式：

- [ ] 核验是否存在官方 API、申请条件、费用和限流。
- [ ] 优先验证后台官方报表能否自动生成和下载。
- [ ] 观察页面正常操作过程中产生的网络响应。
- [ ] 必要时读取稳定的页面 DOM。
- [ ] 只有在稳定性和风险可接受时，才复用后台内部请求。
- [ ] 无法稳定自动获取时，保留“人工导出后上传系统自动处理”的兜底方式。
- [ ] 记录选择该方式的原因、风险、频率和失败处理方式。
- [ ] 不进行绕过验证码、破解签名或规避平台风控的操作。

**本步骤产出：** 每个平台每类数据的采集路径决定。

## 八、优先开发 Temu 两条链路

### Temu 财务数据

- [ ] 建立 Temu 财务适配器和报表解析器。
- [ ] 店铺 A 完成登录检测、筛选、导出和原始文件归档。
- [ ] 完成字段解析、必填校验、重复校验和总计校验。
- [ ] 与财务人员的手工结果逐指标对账。
- [ ] 店铺 B 复用同一适配器，验证多店铺能力。
- [ ] 验证同一任务重复运行不会重复写入经营数据。
- [ ] 验证单个账号登录失效只暂停该账号相关任务。
- [ ] 验证人工导出上传兜底。

### Temu 商品链接数据

- [ ] 确认链接 ID 来源和批量查询入口。
- [ ] 确认查询日期窗口和单批链接数量上限。
- [ ] 店铺 A 至少查询 2 个商品链接。
- [ ] 店铺 B 至少查询 2 个商品链接。
- [ ] 采集曝光、点击率、加购率、转化率和 GMV。
- [ ] 处理无数据、下架、重复和无权限链接。
- [ ] 按店铺、链接 ID 和业务日期进行幂等更新。
- [ ] 与 Temu 运营人员逐链接对账。

**本步骤产出：** Temu 财务和商品链接的两店铺最小闭环。

## 九、并行推进其他平台

不需要等 Temu 连续观察结束后再开发其他平台。

- [ ] Shein：店铺 A 跑通、对账，再复用至店铺 B。
- [ ] TikTok Shop：店铺 A 跑通、对账，再复用至店铺 B。
- [ ] 京东：店铺 A 跑通、对账，再复用至店铺 B。
- [ ] 聚水潭：店铺 A 跑通、对账，再复用至店铺 B。
- [ ] 一个平台进入连续运行观察后，立即继续开发其他平台。
- [ ] 各平台使用独立适配器，不在代码中复制整个采集引擎。
- [ ] 相同平台多个店铺复用同一适配器和解析器。

## 十、每个平台的固定验收流程

- [ ] 两家店铺均能自动获得目标数据。
- [ ] 每次采集均保存原始文件、采集时间和文件哈希。
- [ ] 任务记录能显示开始、完成、失败、等待登录或隔离状态。
- [ ] 必填列、空报表、重复键和总计校验有效。
- [ ] 自动结果与人工结果逐指标一致。
- [ ] 失败后能够从检查点重试，不重复写入已成功数据。
- [ ] 登录失效只暂停受影响账号，其他账号继续执行。
- [ ] 完成一次人工导出上传兜底验证。
- [ ] 填写 `templates/reconciliation-record.csv`。
- [ ] 填写 `templates/platform-validation-scorecard.md`。
- [ ] 启动连续 2 天定时采集观察。
- [ ] 额外完成 1 次管理端手动启动采集。

## 十一、每天收尾必须执行

- [ ] 查看当天所有任务的成功、失败、等待登录和隔离记录。
- [ ] 处理登录失效，但不删除失败证据。
- [ ] 更新问题清单、风险清单和第二天计划。
- [ ] 将当天发现的口径变化交负责人确认。
- [ ] 执行本地备份并确认可读取。
- [ ] 将当天代码提交到独立功能分支。
- [ ] 运行测试、类型检查和构建。
- [ ] 验证通过后推送到私有 GitHub 仓库。
- [ ] 不把客户原始数据、凭证和截图提交到 Git。
- [ ] 不把客户数据复制到个人电脑。

- [ ] Temu 财务至少 2 家店铺完成闭环。
- [ ] Shein 至少 2 家店铺完成闭环。

- [ ] 所有目标链路连续 2 天定时采集成功。
- [ ] 所有目标链路至少完成 1 次手动采集。
- [ ] 财务和运营负责人完成对账确认。
- [ ] 输出仍存在的验证码、风控、权限、延迟和数据质量风险。
- [ ] 填写 `templates/phase-1-feasibility-report.md`。
- [ ] 确认第二阶段平台范围、店铺数量、数据量和展示方式。
- [ ] 确认最终使用飞书多维表格还是自建系统。
- [ ] 确认第二阶段工期、费用和验收标准。

## 十三、现场执行顺序速查

1. 确认人员、范围和数据边界。
2. 检查 Windows 专用电脑。
3. 部署并验证公共底座。
4. 盘点账号、店铺和比特浏览器环境。
5. 完整观察五个平台和 Temu 商品链接的人工流程。
6. 收集样例报表并冻结数据口径。
7. 确定每个数据集的采集路径。
8. 优先开发 Temu 财务和 Temu 商品链接。
9. 并行推进 Shein、TikTok Shop、京东和聚水潭。
10. 每个平台完成两店铺对账后立即进入连续运行观察。
11. 每天备份、提交代码、更新风险和次日计划。
12. 完成连续两天、手动采集、对账和第一阶段报告。
