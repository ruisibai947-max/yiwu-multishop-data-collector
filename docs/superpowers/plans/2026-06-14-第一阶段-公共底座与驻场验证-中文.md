# 第一阶段：公共底座与驻场验证实施计划

> **执行要求：** 实施时使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans`，按照任务和复选框逐项执行。代码、SQL字段、接口路径和命令保持英文，避免执行时发生名称错位。

**目标：** 在不依赖客户真实账号的情况下先完成平台无关的采集底座，再部署到客户 Windows 电脑；驻场获取五个平台的真实人工流程，最终完成每个平台2家店铺，以及 Temu 每店至少2个商品链接的第一阶段闭环验证。

**总体架构：**

- Node.js + TypeScript 服务负责创建和运行采集任务。
- 比特浏览器保存独立登录账号环境。
- Playwright 通过比特浏览器 Local API/CDP 接管浏览器。
- 平台适配器负责各平台特有的登录检测、切店、筛选、导出和页面识别。
- 解析器把 Excel、CSV、JSON 转换成标准数据。
- SQLite 保存任务底账、标准数据、发布状态和原始文件索引。
- React 本地管理页负责店铺、任务、手动采集、异常和原始文件管理。
- 飞书或其他目标系统只是数据出口，不与采集逻辑绑定。

**技术栈：** Node.js 24 LTS、TypeScript、Fastify 5、Playwright Core、比特浏览器 Local API、better-sqlite3、Zod、ExcelJS、csv-parse、React、Vite、Vitest、React Testing Library、Pino。

**版本说明：** 截至2026年6月14日，Node.js 24为最新LTS版本。真正实施任务1时使用 `npm install` 安装当时兼容版本，并通过 `package-lock.json` 锁定，不在文档中写死所有补丁版本。

## 一、范围拆分

在驻场前，我们不知道各平台的真实URL、页面选择器、报表格式、账号权限和指标定义，因此不能提前编造五个平台的真实抓取代码。

本计划分成四部分：

1. 可以在当前电脑提前开发和测试的公共底座。
2. 驻场账号盘点、流程取证和报表口径确认。
3. 现场冻结流程后，为五个平台分别生成精确适配器计划。
4. 第一阶段连续2天运行、手动采集、人工对账和可行性报告。

在拿到现场操作记录和报表样例前，不实现真实 Temu、Shein、TikTok Shop、京东、聚水潭页面选择器。公共底座先用 `mock` 模拟适配器验证。
